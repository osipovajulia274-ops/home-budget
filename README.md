# Домашняя бухгалтерия с нейросетью

Веб-приложение для личных трат: вставляете текст чека, загружаете CSV из банка или вводите трату вручную — классификатор,
обученный с нуля, раскладывает позиции по 13 категориям, а приложение показывает, куда уходят деньги, сравнивает месяц с вашими
прошлыми месяцами, следит за лимитами («цели») и даёт бытовые подсказки.

- Прод: _ссылка появится после деплоя на Render_
- Скриншоты: _будут добавлены после деплоя_

> **Не финансовая консультация.** Приложение описывает ваши траты и даёт бытовые подсказки. Оно не даёт финансовых и
> инвестиционных рекомендаций и **не прогнозирует** будущие траты (решение 2026-10-28: вместо прогноза — сравнение с вашей
> историей и лимиты на месяц).

## Как это работает

```
Браузер (телефон / компьютер)
   │  HTML (Jinja2) + JS (fetch), графики — встроенный SVG
   ▼
FastAPI (один веб-сервис, один воркер)
 ├─ /api/...   импорт чека/CSV → подтверждение → транзакции, итоги, история, цели, советы
 ├─ services/  receipt_parser · csv_import · normalize · categorizer · analytics · history · goals · rules (16 правил)
 └─ ml_artifacts/  TF-IDF по символьным n-граммам + логистическая регрессия (numpy), словари
   ▼
PostgreSQL (Render) / SQLite (локально)
```

Пользователь анонимный: данные привязаны к cookie браузера (демо-режим). Входа и паролей нет; другой браузер — другой пользователь.
Исправленные пользователем категории запоминаются и применяются к следующим импортам.

## Данные

| Источник | Что взято | Лицензия |
|---|---|---|
| Open Food Facts, Open Products Facts, Open Beauty Facts, Open Pet Food Facts | названия товаров для обучения классификатора | ODbL (база), DbCL (содержимое) |
| Receipt OCR RU (CDEK), D6 | реальные чеки — **только для проверки качества** (в обучение не входят) | MIT |
| `data/seed_dictionary.yaml` | словарь услуг и брендов, составлен вручную | собственный, помечен как `seed` |
| Росстат, обследование бюджетов домашних хозяйств | справочные доли расходов | открытые данные |
| Демо-данные, образцы в `data/samples/`, `generated_*.txt` | **синтетика** (вымышленные люди и чеки) | — |

Реальные чеки и разметка в репозиторий не входят (`ml/data/` в `.gitignore`).
Разметка реального теста (2 953 позиции) выполнена Claude и проверена им же повторно, независимой проверки человеком не было —
метрики на реальном тесте нужно читать с этой оговоркой.

## Модели

Классификатор позиций: 13 категорий / 48 подкатегорий. Всё обучено с нуля, предобученные модели не используются.

| Модель | synth acc (кат.) | real acc (кат.) | real macro-F1 (кат.) | real acc без столовой |
|---|---|---|---|---|
| **TF-IDF + логистическая регрессия (в проде)** | 0.850 | **0.629** | **0.614** | 0.869 |
| char-CNN (214 тыс. параметров) | 0.829 | 0.605 | 0.513 | 0.835 |
| ансамбль | 0.844 | 0.627 | 0.548 | 0.851 |

Нейросеть (char-CNN) **не обогнала** простой бейзлайн на реальных чеках, поэтому в продакшене работает бейзлайн
(правило гайда: проигрывающая нейросеть не выкатывается). CNN сохранена в `app/ml_artifacts/classifier.onnx` и в отчёте.

Честные ограничения: 45% реального теста — повторяющееся меню одной столовой (`eating_out.cafe`), поэтому accuracy на нём
занижена, а на остальных позициях выше (см. колонку «без столовой»). Подкатегории считаются хуже категорий. Неуверенные
позиции (<0.5) уходят в «Прочее → не определено»; в интерфейсе позиции с уверенностью <0.7 выделены для проверки.
Отчёты: `ml/reports/metrics_classifier.json`, `confusion_matrix.png`, `errors_examples.md`.

Подтверждение «с нуля»: в `requirements*.txt` нет `transformers`, `pytesseract`, `easyocr`; веса из внешних источников не
загружаются.

## Запуск локально

```bash
pip install -r requirements-dev.txt
# .env не нужен: по умолчанию используется SQLite (dev.db). Для Postgres: DATABASE_URL в .env (см. .env.example)
python -m pytest -q tests/test_pages.py tests/test_api.py
uvicorn app.main:app --reload     # http://127.0.0.1:8000
```

Разбор чека из командной строки: `python -m app.cli receipt generated_1.txt`.
Обучение (Colab/GPU): `pip install -r requirements-train.txt`, ноутбук `ml/notebooks/colab_train.ipynb`.

## Деплой на Render

1. Репозиторий на GitHub → Render → **New → Blueprint** → выбрать репозиторий (используется `render.yaml`:
   веб-сервис + бесплатная БД Postgres).
2. После деплоя проверить `/health` (должен вернуть `{"status":"ok", ...}`).

Ограничения бесплатного тарифа Render:
- сервис засыпает через 15 минут без трафика, первый запрос после сна — около минуты;
- файловая система эфемерная, поэтому все данные — только в Postgres;
- **бесплатная БД истекает через 30 дней после создания** (затем удаляется, бэкапов нет). Дата создания / истечения:
  _заполнить после первого деплоя_. Запасной вариант: Neon (бессрочный бесплатный Postgres) — тот же `DATABASE_URL`.

## Ограничения и планы

- Фото чека (OCR) не реализовано; QR-код чека, дообучение на исправлениях пользователей, вход с паролем — планы.
- Точность классификатора на реальных чеках умеренная (см. выше); пользователь всегда подтверждает позиции перед сохранением.
- Классификатор не учитывает контекст чека (продавца, соседние строки).
